用量重置、算力與 Coding Agent 的需求

從 Codex 用量重置的使用體驗，思考訂閱制、算力與被創造出來的新需求。

Coding Agent / 算力 / 使用心得

最近 codex 短時間內從 6M 飆到 10M 用戶，我感覺大致上是因為：

  1. gpt 5.6 推出了，又可以跟 fable 打了
  2. usage reset 瘋狂大放送，相信開發者都已經開始把項目負責人 Tibo 的 X 開啟小鈴噹了，每天都在看他有沒有放消息要重置
  3. Chatgpt, Codex 的本機 app 兩者合併，應該有蠻多本來不用 Codex 的用戶因此跑去試用

對於我們開發者來說，reset 是最重要的事情，偏偏他選在我上禮拜去沖繩的那個禮拜，但我還是把它燒好燒滿了XD

其實把額度燒完本身從來就不應該是一個指標，我之前好多個禮拜都沒燒完也沒覺得怎樣，只是我最近剛好在趕工作的平台要上線，就完全覺得額度不夠用。

大放送 reset 這件事，從社群上的風向，我感覺應該從 Claude Code 那邊拉了不少用戶。

本質上也是因為大家真的意識到，雖然很多人覺得 Fable 可能還是強一點，但以訂閱制來說，使用成本效益的差距已經大過模型能力帶來的效益了，這當然也是跟上次提到 OpenAI 真的有比較多算力儲備這件事有關。

Anthropic 也被逼跟著 reset 還有延長 fable 的使用期間了，畢竟沒有 fable 就沒有可以跟 5.6 對打的模型。

只是我一直在想一直放送 reset 這件事真的可持續嗎？會不會不送了以後用戶就跑掉了？

我想完以後的結論是偏向否，或者說決定性的因子不在這裡：

第一個原因是訂閱制，背後終究可以隨時調整，且如果調整前後差距不大，用戶也很難判斷。例如有傳聞說 Codex 把 5hr limit 拔掉以後 weekly limit 可用的額度變少了，雖然我是不這樣覺得。

這就有點朝三暮四的概念，reset 好像看起來，當然一定還是有額外成本跟福利沒錯，但終究可以把你控制在一個有效益的範圍內。

第二個原因是 reset 機制其實沒有直覺上那麼划算。（好吧這可能單純是我數字直覺太差）

我自己腦中的直覺一直是：「他送一次 reset 就是我的額度多了 100%」。但其實每 reset 一次，下一次重置的期間會再往後延一個完整的週期。

假設原本每七天重置一次，在週期進行到一半時額外 reset，那麼截至原本第二個週期結束時，累計可用額度不是多 100%，而是只多半個週期，也就是約 50% 的單週額度。

從官方的角度來看，他們一定也有一個 dashboard 去追蹤在哪個時間點重置是成本最低的。

而且我是覺得 will benefit from reset 的人佔他 C side users 的比例應該很低…，前提是他防好中轉商透過這個機制大量薅羊毛就好。

第三個原因就是創造需求…真的會讓使用者回不去，現在用量完全覺得不夠用，哭啊。

其中有幾種因素，首先就是程式碼真的不用自己寫了，而且 use case 現在也越來越多，不僅在程式碼本身，很多電腦 UI 操作的東西也越來越好，前陣子還搞了個 record and replay。

再來就是，回到程式開發來說，就是大家會開始把很多原本 scope 太大做不到的事情排進規劃裡面，像我自己以前換架構這種事情根本不可能去想，但現在也是一次會議就拍板的事情。

甚至還看到有人在討論哪些元件是可以考慮用 Disposable 的概念去做，簡單說就是以前因為維護成本很高，都要做很嚴謹的管控、設計，可是現在例如某些前端元件，不夠用了或是要改丟給 AI 很快就可以做出來，那不如就做一次性的。

總的來說大家多用各家的 Coding Agent（Codex, Claude Code, Antigravity…），不會寫程式的也應該要練習，上次因為去日本我爸記帳覺得很麻煩，我用他的 antigravity 幫他弄就省了很多麻煩。

主要原因其實就是 AI 現在已經做得到很多很多的日常電腦任務，只是要花多少 token 的區別，很厲害很熟的人就可以運用的更有效率。

而且企業的「Token 價格 / 實際成本」短期內應該還是會越來越高，大家趕緊把握還有的玩、有的摸的時間，同樣的任務你可以比別人省多少 token 也是競爭力的一環。

前幾天因為實在燒不夠，問公司可不可以打統編買 pro 帳號，結果因為要關帳了，要等到 8 月才能買…

啊，剩 1% 額度了，趕快下一個要跑兩個小時的 goal 多少薅一點羊毛。
